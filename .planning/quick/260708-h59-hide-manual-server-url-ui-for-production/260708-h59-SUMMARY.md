# Quick Task 260708-h59 Summary

## What changed

Added automatic server-URL detection and hid the manual server URL UI in production deployments.

- `src/main.js`:
  - Added `isAutoServerUrlConfigured()` — returns true when `VITE_WS_URL` is set at build time or the page is served from a non-localhost origin.
  - Added `configureOnlineConnectUI()` — hides the server-address input group, help text, and lobby server-address display when auto-detection is active.
  - Updated the connect button handler to use the default URL when the input group is hidden.
  - Called `configureOnlineConnectUI()` during initialization.

## Why

When deployed to Railway as a single service, the WebSocket server runs on the same origin as the static client. Users had to see a server-address field and the raw URL in the lobby, which was unnecessary and confusing. Now the client auto-connects and the URL is hidden.

## Verification

- `npm run test` — 233 tests pass
- `npm run build` — succeeds

## Notes

- Local development (`localhost` / `127.0.0.1`) still shows the server-address input so developers can point to custom servers.
- If you ever split the client and server onto different Railway services, set `VITE_WS_URL` in the static-site service environment variables and the URL will still be hidden.
